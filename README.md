# Визуализатор графа зависимостей Maven

## 1. Общее описание

Проект представляет собой CLI-приложение на Python для анализа
зависимостей Maven-пакетов.

## Этап 4. Определение порядка загрузки

Программа выводит зависимости в порядке загрузки с учетом максимальной
глубины. Каждая зависимость стоит раньше пакетов, которые ее используют.
Общие зависимости выводятся один раз. Исходный пакет показан отдельно.
При наличии цикла программа сообщает об ошибке.

## 2. Функции и параметры

### Функции

* `load_order(graph, root)` — определяет порядок загрузки обходом без рекурсии.
* `has_cycle(graph)` — проверяет, есть ли цикл в построенном графе.
* `print_result(graph, root, args)` — выводит граф или порядок загрузки.

### Параметры командной строки

| Параметр | Назначение |
| --- | --- |
| `-p`, `--package` | groupId:artifactId или имя из заглавных латинских букв в режиме test. |
| `-r`, `--repository` | URL Maven-репозитория или локальный путь. |
| `-m`, `--mode` | `url` для URL, `path` для локального POM или репозитория, `test` для тестового графа. |
| `-v`, `--version` | Версия пакета. В режиме test не используется. |
| `-t`, `--ascii-tree` | `y` или `n`. Для примеров этапа используется `n`. |
| `-d`, `--max-depth` | Максимальная глубина, целое число от нуля. |
| `--load-order` | Выводит порядок загрузки вместо графа. |

Все параметры, кроме `--load-order`, обязательны.

## 3. Запуск приложения

Для работы нужен Python 3. Команда запускается из корня проекта.

```bash
python3 src/main.py -p A -r tests/pom.xml -m test -v 1 -t n -d 3 --load-order
```

## 4. Примеры использования

Результат запуска для пакета A показан ниже.

```text
Порядок загрузки в пределах глубины 3:
1. D
2. B
3. C
Исходный пакет: A
```

Для других примеров поменяйте пакет и глубину в команде запуска.

| Пакет | Глубина | Результат |
| --- | --- | --- |
| A | 1 | B, C. Транзитивная зависимость D находится за пределами глубины. |
| H | 3 | Пакет без зависимостей. |
| I | 1 | Ошибка из-за зависимости пакета от самого себя. |

### Пример ошибки

Пакеты E, F и G образуют цикл.

```bash
python3 src/main.py -p E -r tests/pom.xml -m test -v 1 -t n -d 3 --load-order
```

```text
Ошибка: Нельзя построить порядок загрузки: обнаружен цикл
```

### Сравнение с Maven

Для сравнения используется JUnit 4.13.2. В файле `maven/pom.xml`
JUnit указан как зависимость демонстрационного проекта.

```bash
python3 src/main.py -p junit:junit -r https://repo.maven.apache.org/maven2 \
  -m url -v 4.13.2 -t n -d 2 --load-order
mvn -f maven/pom.xml -B org.apache.maven.plugins:maven-dependency-plugin:3.8.1:resolve
```

Визуализатор выводит `hamcrest-core:1.3` и `hamcrest-library:1.3`.
Maven разрешает JUnit и `hamcrest-core:1.3`. У `hamcrest-library`
в POM JUnit указана область `test`, поэтому Maven исключает ее из
зависимостей проекта-потребителя. Визуализатор учитывает все объявления.

В опыте с пустым кешем Maven скачал JAR JUnit перед JAR hamcrest-core.
Порядок скачивания файлов может отличаться от порядка в графе,
где hamcrest-core предшествует JUnit.
Для повторения опыта добавьте к команде Maven
`-Dmaven.repo.local=../stage4-cache` с путем к новой пустой папке.
